# 使い方

intro-bot の運用ガイド。Bot 招待後の設定方法、メンバー目線の動作、管理者向けスラッシュコマンドの解説。

セットアップ(環境変数 / デプロイ)と招待手順は [README.md](../README.md) を参照。

## ギルドごとの初期設定

招待直後は **自己紹介チャンネルが未設定** の状態で、自動投稿は何も起きない。サーバー管理者が以下を実行して初期設定を行う。

```
/intro-config intro-channel channel:#自己紹介
```

- 設定は対象ギルドのみに反映される(他のギルドには影響しない)
- 設定値は Postgres の `bot_config` テーブルに `(guild_id, intro_channel_id, cooldown_seconds)` として永続化される
- クールダウンを変更する場合は `/intro-config cooldown seconds:1800` のように指定(デフォルトは環境変数 `COOLDOWN_SECONDS` で 60 秒)
- 設定状況は `/intro-config show` で確認できる

## メンバーの使い方

メンバーは「自己紹介チャンネル」に **本文ありの** メッセージとして自分の自己紹介を投稿する。

- Bot は **本文が空でない最新の投稿** を自己紹介として採用する
- 添付のみ(本文なし)のメッセージは自己紹介として扱われない
- 自己紹介を更新したい場合は、新しいメッセージとして再投稿するか、既存メッセージを編集する

その後、対象サーバーの VC に入室すると、その VC のテキストチャットに自分の自己紹介が自動で埋め込み投稿される。

## 動作の挙動

| 動作 | 投稿される? |
|------|-------------|
| VC に新規入室 | ✅ |
| VC 間を移動 | ✅(移動先に投稿) |
| VC を退室 | — |
| 同一 VC 内でミュート/配信開始/カメラ ON 等 | — |
| ステージチャンネルへ入室 | — (対象外) |
| `/intro-config exclude-vc` で除外した VC へ入室 | — (対象外) |
| 自己紹介未登録者が `/intro-config nudge-exempt-role` のロールを持つ | 埋め込みは投稿されない / 未記入リマインドも飛ばない |

### クールダウン

同一ユーザーが同じ VC に連続で出入りしても投稿が連投されないよう、**デフォルト 1 分(60 秒)** のクールダウンが設定されている。

- スコープは **ユーザー単位 + VC 単位 + ギルド単位**
- A VC に入って投稿 → すぐ B VC に移動した場合は、B には新たに投稿される(VC が違えば独立)
- A VC に入って投稿 → 30 秒後に再び A VC に入り直した場合は、A には再投稿されない
- 別ギルドのクールダウンは独立(ギルド A で投稿済みでも、ギルド B では普通に投稿される)
- クールダウンは「埋め込み投稿が成功した時刻」から起算。投稿失敗・自己紹介未登録の場合はリセットされない
- Bot が再起動するとクールダウン状態はリセットされる(設定値そのものは Postgres に永続化)
- 秒数はギルドごとに `/intro-config cooldown` で変更できる

### 通知抑制

埋め込み内のメンションは表示されるが、実際の通知は飛ばない(`allowed_mentions=False`)。

### レベル表示(任意 / level-bot 連携)

環境変数 `LEVEL_API_BASE` で [level-bot](../../level-bot) の API を指定している場合、埋め込みの **footer に総合レベルと進捗** が表示される(例: `Lv. 12 (45%)`)。

- 表示対象は自動投稿 / `/intros` / `/intro` すべて
- レベルに応じて解放される「チル場所」も自己紹介 embed に短く表示される
- level-bot 側でそのギルドが非公開設定、対象ユーザーに stats が無い、API がタイムアウト/応答エラーなどの場合は **footer なしで通常通り投稿される**(機能が無効化されているように見えるだけで、自己紹介投稿そのものは止まらない)
- レベルは `LEVEL_CACHE_TTL_SECONDS`(デフォルト 60 秒)の間プロセス内にキャッシュされ、短時間の連続 VC 移動では再 fetch されない
- Bot を再起動するとキャッシュはクリアされる

### チル場所(任意 / level-bot 連携)

level-bot 連携が有効な場合、ユーザーの現在レベルに応じて自己紹介 embed に「チル場所」が表示される。プリセットの場所には絵文字、短い説明、雰囲気タグが付き、未選択の場合は現在レベルで解放済みのうち一番高い場所を自動表示する。メンバーは `/intro-chill set` で、解放済みの場所を名前の候補から選べる。

チル場所の表示・一覧・選択肢は level-bot API を優先して読む。level-bot API が未設定または取得に失敗した場合のみ、intro-bot 側 DB の値に fallback する。

デフォルトの解放プリセット:

```

Lv.2   🛋️ ロビーソファ
Lv.3   🪟 窓際スツール
Lv.4   ☕ 小さな丸テーブル
Lv.5   🥤 カフェカウンター
Lv.6   📚 本棚のそば
Lv.7   🪴 観葉植物の横
Lv.8   💤 ふかふかチェア
Lv.9   🔌 充電席
Lv.10  ☕ いつものカフェ席
Lv.12  📝 静かな作業机
Lv.14  📖 本棚奥の席
Lv.16  🌙 夜更かしテーブル
Lv.18  🕯️ 半個室ソファ
Lv.20  🍵 チルラウンジ
Lv.25  🌤️ 窓辺の作業部屋

```

管理者は `/intro-config chill-place add` で同じレベルの場所名や絵文字を上書きしたり、新しい解放レベルを追加できる。絵文字は標準絵文字推奨だが、Discord のカスタム絵文字文字列も入力できる。`remove` はカスタム設定だけを削除し、プリセットの場所は残る。

自己紹介 embed の表示例:

```

```

`/intro-chill mine` ではタグや説明を含む詳しい表示を確認できる。

### ユーザー統計サイトリンク(任意 / level-bot 連携)

環境変数 `USER_STATS_SITE_GUILD_ID` と `USER_STATS_SITE_BASE_URL` を設定すると、対象ギルドの自己紹介埋め込みに `/level` と同じ **30日間の統計リンク** が追加される。

- リンク先は `{USER_STATS_SITE_BASE_URL}/u/{user_id}/level?days=30`
- 自動投稿 / `/intro` では「ユーザー統計を開く」ボタンが表示される
- `/intros` は複数人をまとめて送るため、各 embed 内リンクのみ表示される
- `USER_STATS_SITE_GUILD_ID` と投稿先ギルド ID が一致しない場合、リンクは表示されない

### 外部 API(任意)

HTTP API は Bot と別プロセスで `./scripts/start-api.sh` として起動する。API は Discord Gateway に接続せず、Bot が同期した `intro_messages` テーブルと level-bot API から、自己紹介 embed に表示する材料を JSON で返す。また、信頼済みサービスからのチル場所選択更新にも使える。`Authorization: Bearer <INTRO_API_KEY>` が必要で、`INTRO_API_KEY` が未設定の場合は `EXTERNAL_API_KEY` を流用し、どちらも空なら API は常に `401 Unauthorized` を返す。
Bearer 認証失敗は IP 単位で `INTRO_API_AUTH_FAILURE_WINDOW_SECONDS` 秒あたり `INTRO_API_AUTH_FAILURE_LIMIT` 回を超えると `429 Too Many Requests` になる。Railway では API サービスの Start Command を `./scripts/start-api.sh` にし、`INTRO_API_PORT` は未設定にして Railway が注入する `PORT` を使う。
API の詳細なリクエスト/レスポンス仕様は [API ドキュメント](api.md) を参照。

CORS はデフォルトでは無効。ブラウザから別オリジンで叩く場合は、`INTRO_API_CORS_ORIGINS=https://example.com,https://admin.example.com` のように許可 Origin を明示する。server-to-server 利用だけなら空のままでよい。ブラウザに `INTRO_API_KEY` を置くと利用者から見えるため、公開フロントエンドではサーバー側 proxy 経由を推奨する。

```
GET /api/v1/guilds/{guild_id}/users/{user_id}/intro
Authorization: Bearer <INTRO_API_KEY>
```

返却内容:

- メンバー表示名 / アバター URL
- 自己紹介本文 / ジャンプ URL / 添付画像 URL
- level-bot 連携のレベル情報
- チル場所の現在地 / 次の解放 / 表示用テキスト
- ユーザー統計サイト URL

例:

```bash
curl -H "Authorization: Bearer $INTRO_API_KEY" \
  "https://intro-bot.example.com/api/v1/guilds/123/users/456/intro"
```

## メンバー向けスラッシュコマンド

サーバーメンバー全員が実行可能。クールダウンは無視され、何度でも実行できる(自動投稿のクールダウンとは独立)。

### `/intros`

実行者が参加している VC のメンバー全員(Bot を除く)の自己紹介を一括表示する。VC のテキストチャットで実行した場合は、その VC が対象になる。

- 通常のテキストチャンネルからでも、実行者が VC に参加していれば使える
- VC に参加していない場合は ephemeral でエラー
- VC に誰もいない場合は ephemeral で「VC に誰もいません」
- 自己紹介を投稿していないメンバーがいた場合、本人のみに見える ephemeral メッセージで未登録者リストを通知(VC 全体には晒さない)
- Discord の制限により 1 メッセージ 10 embed まで。VC に 11 人以上いる場合は複数メッセージに分割される

### `/intro [user]`

指定したメンバーの自己紹介を表示する。`user` を省略した場合、VC 参加中は同じ VC のメンバーを実行ごとに順番に表示し、VC 外では自分の自己紹介を表示する。

- どのチャンネルからでも実行可能
- 対象が Bot の場合 / 自己紹介が未登録の場合は ephemeral で通知
- VC のテキストチャットから実行すれば、VC 全員に対して見える形で投稿される

### `/intro-help [topic]`

intro-bot の使い方を ephemeral で表示する。`topic` は `基本` / `チル場所` / `管理者設定` から選べる。

### `/intro-chill list`

レベルごとのチル場所一覧と、自分の解放状況を表示する。現在レベルを取得できない場合は、場所一覧のみ表示する。

### `/intro-chill set <place>`

自己紹介 embed に表示するチル場所を選ぶ。

- `place` はドロップダウン候補から場所名で選ぶ
- 現在レベル以下で解放済みの場所だけ候補に表示される
- 未選択の場合は、現在レベルで解放済みの一番高い場所を自動表示する
- 設定完了メッセージは通常メッセージで表示される
- 単体の自己紹介 embed では、下の「チル場所を設定」ボタンから本人だけに見えるドロップダウンを開いて選択できる

### `/intro-chill mine`

現在のチル場所と次に解放される場所を表示する。
結果は通常メッセージで表示される。

### `/intro-chill clear`

チル場所の選択を解除する。解除後は、現在レベルで解放済みの一番高い場所を自動表示する。
解除完了メッセージは通常メッセージで表示される。

## 管理者向けスラッシュコマンド

`Administrator` 権限を持つメンバーのみが実行可能。Discord クライアント側で非管理者には表示されないが、コード側でも二重に検証している。各コマンドはコマンドが実行された **ギルド単位** に作用する(他のギルドの設定には影響しない)。

### `/intro-config show`

現在のギルド設定を **ephemeral**(自分にしか見えないメッセージ)で表示する。未設定のギルドでは `intro_channel: 未設定` と返る。

```
intro_channel: #自己紹介
cooldown_seconds: 60
excluded_vcs: #ロビー, #作業部屋
nudge_exempt_roles: @ゲスト, @Bot運用
```

### `/intro-config intro-channel <channel>`

このギルドの自己紹介チャンネルを設定する(未設定なら新規作成、設定済みなら更新)。

- 対象は `TextChannel` のみ選択可能
- 設定時にこのギルドのメッセージキャッシュがクリアされ、既存自己紹介が API 用 DB に同期される
- 設定内容は DB(`bot_config` テーブル)に永続化される
- これを実行するまで、自動投稿および `/intros` / `/intro` は動作しない

### `/intro-config cooldown <seconds>`

このギルドのクールダウン秒数を変更する。

- 値の範囲は **1〜86400 秒**(1 秒〜1 日)
- 即時反映。すでに最終投稿から経過した時間にそのまま新しい閾値が適用される(例: 30 分前に投稿したユーザーがいる状態で 1800 秒に変更すると、その時点でクールダウンが解除される)
- 設定内容は DB に永続化される

### `/intro-config sync-intros`

自己紹介チャンネルの既存投稿を API 用 DB(`intro_messages`)に同期する。

- 各ユーザーの最新の本文あり投稿だけを同期する
- API を追加した直後や、同期状態を明示的に更新したいときに使う
- 設定済みの自己紹介チャンネルを履歴走査するため、Bot に `Read Message History` が必要

### `/intro-config chill-place add <level> <name> [emoji]`

レベルごとのチル場所を追加または変更する。

- `level` は 1〜1000
- `name` は 1〜80 文字
- `emoji` は任意。標準絵文字推奨。省略するとプリセットの絵文字があれば引き継ぐ
- プリセットと同じ `level` を指定すると、そのギルドでは場所名が上書きされる
- プリセットにない `level` を指定すると、新しい解放場所として追加される

### `/intro-config chill-place remove <level>`

指定レベルのカスタム設定を削除する。プリセットの場所は削除されないため、プリセットと同じ `level` のカスタム設定を削除すると元の場所名に戻る。

### `/intro-config chill-place list`

現在このギルドで有効なチル場所一覧を ephemeral で表示する。プリセットとカスタム設定を統合した結果が表示される。

### `/intro-config exclude-vc add <channel>`

指定 VC を自動投稿の対象から外す(その VC への入室では埋め込みも未記入リマインドも投稿しない)。

- 対象は `VoiceChannel` のみ選択可能
- メンバー向けスラッシュコマンド(`/intros` / `/intro`)は除外 VC でも通常通り動作する
- すでに除外済みの VC を指定した場合は ephemeral で通知されるだけで状態は変わらない
- 設定内容は DB(`bot_config.excluded_vc_ids`)に永続化される

### `/intro-config exclude-vc remove <channel>`

`exclude-vc add` で外した VC を自動投稿の対象に戻す。除外リストに含まれていない VC を指定した場合は ephemeral で通知される。

### `/intro-config exclude-vc list`

現在このギルドで除外している VC の一覧を ephemeral で表示する。除外がない場合は「除外 VC はありません。」と返る。
削除済み、または Bot からアクセスできなくなった VC が除外リストに残っている場合は、チャンネル削除/権限更新の検知時や、この一覧表示、`/intro-config show` の実行時に自動で解除される。

### `/intro-config nudge-exempt-role add <role>`

自己紹介が未記入のメンバーが VC に入室した際の催促メッセージを、指定ロールを持つメンバーに対して送らないようにする。

- 自己紹介が **登録済み** のメンバーには影響しない(従来通り埋め込みが投稿される)
- 複数のロールを登録可能で、いずれかのロールを持っていれば催促はスキップされる
- すでに除外済みのロールを指定した場合は ephemeral で通知されるだけで状態は変わらない
- 設定内容は DB(`bot_config.nudge_exempt_role_ids`)に永続化される

### `/intro-config nudge-exempt-role remove <role>`

`nudge-exempt-role add` で外したロールを催促の対象に戻す。除外リストに含まれていないロールを指定した場合は ephemeral で通知される。

### `/intro-config nudge-exempt-role list`

現在このギルドで催促を送らないロールの一覧を ephemeral で表示する。設定がない場合は「除外ロールはありません。」と返る。

## トラブルシューティング

| 症状 | 確認ポイント |
|------|---------------|
| VC 入室しても投稿されない | `/intro-config show` で自己紹介チャンネルが設定されているか確認 / Bot に対象チャンネル(自己紹介・VC 両方)の権限があるか / クールダウン中ではないか / そもそも自己紹介を投稿しているか |
| 招待後に何も起きない | 招待直後はチャンネル未設定。管理者が `/intro-config intro-channel` で設定する必要がある |
| `/intro-config` がメニューに出ない | サーバー管理者権限を持っているか / Bot 招待時に `applications.commands` scope を含めたか |
| 自己紹介を編集しても反映されない | Bot は次回 VC 入室時に最新の本文を取得する。すぐ確認したい場合は VC を一度退室して再入室(クールダウン中なら時間を置く) |
| 埋め込みの末尾に `…` が付いている | 自己紹介本文が 4000 文字を超えたため切り詰められている。フィールドの「ジャンプ」リンクから元投稿へ飛べる |
| ステージチャンネルで動作しない | 仕様(対象外) |
| 設定変更後も古い値で動作している | DB 接続が切れていないか Logs を確認。実行中の DB 障害は `/intro-config` の更新失敗を引き起こすが、メモリ上の設定で投稿動作は継続する |
| `/intros` が「VC のテキストチャットで実行してください」と返す | 通常のテキストチャンネルから実行している。VC に入って、その VC のチャットアイコンから入力する |
| 埋め込み footer にレベルが表示されない | `LEVEL_API_BASE` が設定されているか / level-bot 側でそのギルドが公開設定か / 対象ユーザーに stats があるか。設定されていないか取得に失敗した場合は footer なしで投稿される(仕様) |
